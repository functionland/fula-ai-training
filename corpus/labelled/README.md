# corpus/labelled/

This directory is the SFT corpus the LoRA trainer consumes. It contains `*.labelled.json` files in two flavors:

1. **Synthetic** (`synthetic_*.labelled.json`) — generated by `corpus/synthetic/generate.py`. Bootstrap data shipped 2026-05-27 to enable initial Qwen 3 1.7B fine-tuning before real anonymized user transcripts accumulate. ~170 examples covering all runbook sections + adversarial failure modes. See `corpus/synthetic/README.md` for composition + regeneration.

2. **Real** (any other `<upload_id>.labelled.json`) — written by the operator via `labeller/app.py` after reviewing anonymized transcripts uploaded through the Phase 21 opt-in path. Schema identical to synthetic so the trainer doesn't care which is which.

**For the full operational workflow** (how new real transcripts become a new published model, how to iterate with Claude assistance, how to interpret eval reports, how to roll back): see [`OPERATIONS.md`](../../OPERATIONS.md) at the repo root, especially the "Iteration loop — turning new logs into a better model" section.

## Training

Use the multi-turn ChatML-aware trainer for Qwen 3:

```bash
# 1. Install dependencies on your GPU box
pip install torch transformers peft datasets trl pyyaml accelerate

# 2. Dry-run first to confirm the corpus parses + your tokenizer downloads
python -m training.train_qwen3_messages \
    --config training/configs/qwen3_1_7b_lora.yaml \
    --dry-run

# 3. Verify the loss mask isolates only assistant tokens
#    (run on the same GPU box; needs `transformers` for the tokenizer)
python -m training.verify_mask \
    --config training/configs/qwen3_1_7b_lora.yaml \
    --sample 0

# 4. Run the actual fine-tune
python -m training.train_qwen3_messages \
    --config training/configs/qwen3_1_7b_lora.yaml
```

The trainer uses TRL's `DataCollatorForCompletionOnlyLM` for loss masking (config flag `chat_template.mask_user_and_tool: true`). This masks user/system tokens before the first assistant turn so the model trains only on its own outputs. Set the flag to `false` if you want to skip masking (simpler, slightly slower convergence).

The legacy `training/lora_train.py` trainer (Qwen 2.5 3B, flat prompt+completion shape) is left in place for the older config (`training/configs/qwen3b_lora.yaml`) — do NOT use it for Qwen 3.

## Privacy

Synthetic transcripts contain no PII (they're machine-generated from schema). Real transcripts arrive already-anonymized from the phone (per Phase 21's `anonymizeTranscript.ts` — peerIds, IPs, paths, SSIDs, BSSIDs, timestamps stripped). The intake server runs a defense-in-depth PII scanner. If you find PII in a labelled.json file, that's an intake-server bug — fix it + re-evaluate every affected transcript before training on it.
